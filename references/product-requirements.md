# 제품 요구사항

## 제품 목적

AI, Security, AI × Security 분야로 취업을 준비하는 사용자가 대한민국 채용 공고와 국내외 분야 변화를 한곳에서 추적하도록 돕는다.

제품은 다음 두 기능과 두 Notion data source로 구성한다.

- `Job Discovery`: 대한민국 근무 채용 공고를 찾고 공고 본문에서 직무를 인식해 Jobs DB에 저장한다.
- `Trend Update`: AI, Security, AI × Security 분야의 기술·산업·연구·정책·채용시장 동향을 Trends DB에 저장한다.

별도 Roles DB, Role Discovery와 Candidate 승인·거절은 새 workflow에서 사용하지 않는다. 직무 인식은 Jobs의 검색·분류값이며 공고 저장을 막는 사전 허용 목록이 아니다.

## 공통 동작

- 사용자는 JSON이나 명령줄 형식 대신 자연어로 요청한다.
- 기간을 지정하지 않으면 최근 7일을 사용한다.
- Codex 웹 검색을 초기 검색 수단으로 사용하되 검색 provider를 교체 가능한 경계로 둔다.
- AI, Security, AI × Security는 검색 경로이자 분류값으로 유지한다.
- 원본 URL과 확인된 모든 관련 URL을 보존한다.
- 커뮤니티, 소셜 네트워크, 일반 포럼과 익명 게시물은 수집 출처에서 제외한다.
- 실행하지 않은 검색이나 쓰기를 완료했다고 보고하지 않는다.

## Job Discovery 요구사항

- 기업 공식 채용 페이지와 Saramin, JobKorea, Wanted, Jumpit을 우선 검색하되 완전한 허용 목록으로 사용하지 않는다.
- 다른 사이트를 사용할 때도 공고 원문에서 대한민국 근무를 확인하고 가능하면 기업 원본을 함께 확인한다.
- 공고 제목뿐 아니라 업무, 자격 요건, 기술, 팀과 제품 맥락을 평가한다.
- 원문의 정확한 공고명과 회사명, 근무지, 경력 수준, 업무·요건, 게시일·마감일·모집 상태를 확인 가능한 범위에서 기록한다.
- 경력 수준은 신입, 경력, 신입·경력, 미확인 중 하나이며 직무명만으로 추정하지 않는다.
- 확인 가능한 공고 원문 한 건이면 저장 후보가 될 수 있다. 두 번째 독립 근거나 별도 정보글을 필수로 요구하지 않는다.
- 게시일이 기간 안이면 확정 결과로 판정한다. 게시일이 없지만 현재 모집 중이면 게시일 미확인 검토 대상으로 남긴다.
- 해외 근무, 기간 밖 공고와 실제 업무가 무관한 공고는 제외한다. 근무지가 불명확한 공고는 저장하지 않는다.
- 각 공고를 적합, 검토 필요, 제외, 중복으로 독립 판정한다. 한 공고의 오류가 다른 공고 처리를 막지 않는다.
- 중복은 URL, 플랫폼 공고 ID, 회사명·원문 공고명·근무지·날짜 순으로 공고 단위에서 판정한다.
- 동일 공고의 복제 URL은 하나의 Jobs 행에 관련 URL로 보존한다.

## Trend Update 요구사항

- Jobs DB의 관심 상태나 승인 상태에 의존하지 않고 AI, Security, AI × Security 분야를 직접 검색한다.
- 기술·산업·연구·제품·정책·위협 동향은 해외 출처도 허용한다.
- 채용 자료를 동향 근거로 사용할 때는 대한민국 근무가 확인된 경우만 허용한다.
- 사실 중심의 요약과 취업 관점의 시사점을 분리한다.
- 하나 이상의 관련 분야와 영향을 받는 직무 유형, 기술 키워드, 동향 유형과 지역 범위를 기록한다.
- 원문 게시일이 없거나 요청 기간 밖인 자료는 저장하지 않는다.
- 정규화된 URL이 기존 원문 URL과 같으면 중복으로 저장하지 않는다.

## Notion 구조

프로젝트 페이지의 하나의 운영 database container에서 `Jobs`와 `Trends`를 탭으로 보여준다. 현재 운영 확인 절차는 [Notion 데이터베이스 지침](notion-databases.md)을 따르며, [Job Discovery Notion 이전 계획](notion-job-discovery-migration-plan.md)은 완료된 이전의 역사 기록으로만 사용한다.

- Jobs의 한 행은 실제 채용 공고 한 건이다.
- Trends의 한 행은 원문 콘텐츠 한 건이다.
- Trends의 `관련 직무`는 Roles relation이 아닌 Multi-select이다.
- 기존 Roles 1건은 Jobs의 `검토 필요` 행으로 이전했다. Trends 원본 data source의 소유 위치를 운영 container로 옮기고 검증한 뒤 보관 페이지와 기존 Roles DB를 삭제했으므로 다시 만들지 않는다.
- 실제 schema와 데이터 변경 전 사용자에게 변경 목록을 보여주고 승인을 받는다.

## 언어 지침

- PR 제목·설명·검토 코멘트는 한국어로 작성한다.
- commit 메시지는 영어 유형 뒤에 한국어 설명을 사용한다.
- 사용자가 읽는 문서는 한국어로 작성한다.
- Skill 이름, 기능명, branch명, 코드 식별자, 설정 키, 명령어와 내부 enum은 영어로 유지한다.
- Notion 속성명과 옵션은 한글로 표시하되 AI, Security, AI × Security, GitHub는 유지한다.

## 구현 단계

1. Job Observation과 공고별 판정·중복 경계
2. Job Discovery 조사·검토 Agent와 Skill workflow
3. Jobs·Trends schema 코드와 기존 데이터 이전
4. Job Discovery 운영 저장 경계와 실사용 시험
5. Jobs와 독립적인 Trend Update와 Trends 저장 경계
6. 같은 기간·출처 범위의 Trend Update 실사용 시험

각 단계는 관련 자동 시험, Python 문법 검사와 Skill 구조 검사를 통과해야 한다. 사용자의 명시적 승인 없이 Notion을 변경하거나 branch를 main에 병합하지 않는다.

## 현재 제외 범위

- 의미만으로 서로 다른 공고를 자동 병합
- 모집 상태의 예약 재확인
- 급여와 회사별 채용 규모 분석
- 이메일 뉴스레터 직접 수집
- 자동 주간 보고서
- 지원서 제출이나 기업에 대한 자동 연락
